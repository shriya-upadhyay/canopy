# Conditional settlement — working notes

**Agents pay for outcomes, not promises.** Buyer authorizes *up to* $0.50 for a
signal. It resolves over 3 minutes. Settlement scales with realized accuracy —
a wrong signal settles at **$0 with no on-chain transaction**.

facilitator. Payment + settlement untested — needs funded wallets.

## Two gotchas already hit and fixed

**1. `server.initialize()` is mandatory.** It fetches the facilitator's
supported kinds from `GET /supported`. Without it you get either
`accepts: []` — a 402 the client can never satisfy — or
`"Facilitator does not support upto on eip155:10143"`. Neither message points at
the real cause. Handled by `initialized()` in `lib/x402.ts`, cached per process;
`await` it before `buildPaymentRequirements`.

**2. `ResourceConfig` is flat.** `buildPaymentRequirements()` takes
`{ scheme, payTo, price, network }` — *not* the nested
`{ accepts: {...}, resource }` shape in the Monad guide. That nested one is
`RouteConfig`, which belongs to the `withX402` wrapper. Passing it silently
yields an empty `accepts`.

```json
    "scheme": "upto", "network": "eip155:10143",
    "amount": "500000", "asset": "0x534b2f3A21130d7a60830c2Df862319e593943A3",
    "maxTimeoutSeconds": 300,
    "extra": { "name": "USDC", "version": "2",
               "assetTransferMethod": "permit2",
               "facilitatorAddress": "0x7f6a2850669202519f0FE8aa912451238820Db86" }}]}
```

`amount: "500000"` = $0.50 at 6dp. Note the server injects `facilitatorAddress`
into `extra` automatically, so the client doesn't bind it by hand.

## The mechanism

`settlePayment` takes a 5th arg:

```ts
interface SettlementOverrides {
  amount: string;  // "1000" atomic | "50%" of max | "$0.05"
}
```

> *"Must be <= the authorized maximum. Setting this to an amount other than
> `PaymentRequirements.amount` is only valid in schemes that support partial
> settlement, such as `upto`."*

So pricing is one string — `lib/x402.ts` → `settleForAccuracy()`:

```ts
server.settlePayment(payload, reqs, undefined, undefined, {
  amount: `${(accuracy * 100).toFixed(2)}%`   // "0.00%" when wrong
});
```

No escrow contract. The sponsor shipped it.

## The architectural catch

`withX402` verifies **and settles in the same request**. The signal resolves 3
minutes later, so it's unusable here. `verify` and `settle` are separate
facilitator calls, so we split them and hold the payload in between — that's all
`lib/pending.ts` is (in-memory; the whole lifecycle is ~3 min).
